# 供应商主体审校台 · 包装单位换算台

用于归集两套采购系统中的供应商记录：审核企业名称相同的记录对，给出“同一企业 / 不同企业”判定，形成入仓时使用的统一主体分组；并按供应商原始记录维护包装单位换算等式，把采购量以**精确最简分数**换算为“件”。

- 后端：FastAPI + SQLite（WAL、`BEGIN IMMEDIATE` 事务、`busy_timeout`）
- 前端：两个无外部依赖的单页网页（主体审校页 `/`、包装单位换算页 `/convert`）
- 运行形态：Docker Compose 启动 **两个独立 Web 进程**（`app1`、`app2`），nginx 作为浏览器入口轮询转发，两个进程共享同一个 SQLite 数据卷
- 浏览器入口：**http://localhost:8080**

## 快速启动

前置条件：Docker 与 Docker Compose v2。

```bash
docker compose up --build
```

等待两个应用健康检查通过后打开：

- 主体审校台：**http://localhost:8080/**
- 包装单位换算台：**http://localhost:8080/convert**（首页右上角也有入口）

首次启动会从 `data/suppliers.csv` 导入最多 100 条 `来源 / 源编号 / 企业名称` 记录；本仓库附带 62 条示例记录（两套采购系统各 31 条）。之后原始记录只读，重启不会重新导入，也不会覆盖已有判定、分组和换算等式。

停止：

```bash
docker compose down
```

如需清空全部数据、从 CSV 重新演示（**会删除数据卷中的判定、分组与换算等式**）：

```bash
docker compose down -v
docker compose up --build
```

## 包装单位换算页（新）

### 数据模型

- 换算等式挂在**供应商原始记录**上，例如在记录 A-001 上添加 `2箱=24件`，含义为 1箱 = 12件。
- 每条等式包含两个**非空单位名**与两个**正整数数量**，且两端单位不能相同；每条原始记录最多 **20 条**等式。
- 等式自动归入该记录当前所在的供应商分组。分组由主体审校页的“同一企业”判定决定。

### 换算查询

输入“供应商原始记录 + 采购单位 + 正整数采购量”，系统：

1. 定位该记录的**当前分组**，只加载该组内来源的等式（其他组的等式不可见）；
2. 在等式图上做最短路搜索，等式是无向边，天然支持**反向**与**多跳**换算；
3. 全程使用有理数（`fractions.Fraction`）运算，返回**精确的最简分数**件数（整数则直接显示整数），并返回经过的每一跳等式及其供应商来源；
4. 组内不存在到“件”的通路时返回缺失提示，并列出从输入单位实际可达的单位，提示需要补充哪段等式。

示例：组内有 `2箱=24件` 与 `3盒=1箱`，查询 `2盒`：

```text
2盒 → 3盒=1箱（#2）→ 2箱=24件（#1） = 8件
```

### 一致性规则

- **组内闭环比例矛盾拒绝新增**：同一组内任意两个单位之间只能有一个比例。已有 `2箱=24件`（1箱=12件）时，再添加 `1箱=13件` 会被拒绝，响应中指出矛盾等式与两个比例，且不写入任何数据。
- **关系合并的预览和确认都检查拟组**：把两个分组合并为“同一企业”时，会先在拟合并的等式并集上做闭环校验；若矛盾，预览直接不可确认并指出矛盾等式。确认时在写事务内按**最新状态**再次校验，两个进程并发操作时后提交者会被拒绝，不会形成矛盾组。
- **拆分后只用各自来源**：撤回“同一企业”判定导致分组拆分后，每条查询只使用自己当前组内记录贡献的等式。
- **整体提交**：等式增删与关系确认均在单个 `BEGIN IMMEDIATE` 事务内完成“读最新状态 → 校验 → 写入”，失败一律回滚，不改状态。
- **同一已提交状态**：换算查询在单个只读事务内同时读取分组、等式并计算结果，响应附带 `state_version`（分组 + 判定 + 等式的摘要），保证三者来自同一已提交快照。
- **重启保留**：等式持久化在 SQLite 的 `unit_equations` 表中。

## 主体审校台演示路径

### 1. 合并同名企业

1. 页面默认展示 62 条原始记录、62 个单条分组。
2. 在“同名企业候选对”中找到“华信精密制造有限公司”（A-001 / B-001），点击“同一企业”。
3. 页面先弹出预览：受影响记录的变更前/变更后分组、判定依据、变更摘要；若两个分组的换算等式在拟组内矛盾，会直接展示矛盾等式且无法确认。
4. 点击“确认保存判定与分组”。返回后分组变为 61 个，“已归并分组”增加 1。
5. 用“判定工作台”再选另一条已归并记录与第三条记录判定“同一企业”，可看到同一关系传递成组（三条记录进入同一分组）。

### 2. 不同企业约束与冲突拦截

1. 对同一分组内的两条记录选择“不同企业”，预览会显示拦截原因和“同一企业”传递路径，不提供确认按钮。
2. 对两个不同分组选择“不同企业”可正常保存；此后任何会把这二者合并的“同一企业”判定都会在预览时被拒绝。

### 3. 撤回只移除一条判定

在“判定依据”或分组卡片中点击某条判定的“撤回”：

1. 先预览“撤回后分组”，例如一个分组拆成两个分组。
2. 确认后只删除该一条判定，其余同一企业关系继续生效，分组自动重算；换算页随后按新分组隔离等式来源。

### 4. 两个 Web 进程

页面右上角的“服务进程”显示本次响应来自 `app1` 还是 `app2`。点击“刷新”多次，nginx 会在这两个进程之间轮询；无论请求落到哪个进程，看到的分组、判定与等式都一致，因为所有读写都通过共享 SQLite 事务完成。

```bash
docker compose logs -f app1 app2
```

也可以直接观察响应头：

```bash
for i in 1 2 3 4; do
  curl -s -D - -o /dev/null http://localhost:8080/health | grep -i x-app-instance
done
```

### 5. 确认时的重新校验（两个标签页演示）

打开两个浏览器标签页，均指向 http://localhost:8080。

**相关改动 → 拒绝并要求重新预览：**

1. 标签页 1：对 A-001 与 B-001 点“同一企业”，停留在预览弹窗，不确认。
2. 标签页 2：对 B-001 与另一条记录（例如 A-002）判定“同一企业”并确认；或在换算页向所涉分组添加一条等式。
3. 回到标签页 1 点击确认：系统在写事务中重新读取所涉原组成员、关联判定与组内等式，发现快照已变化，返回“预览已失效”（若新等式造成比例矛盾则返回具体的矛盾等式），判定、分组与等式均未改变。
4. 点击弹窗中的“重新预览”，确认新的前后分组后再保存。

**无关分组改动 → 不影响确认：**

1. 标签页 1：对 A-001 / B-001 预览“同一企业”，不确认。
2. 标签页 2：对完全无关的“恒达电子科技有限公司”两条记录判定“同一企业”并确认，或向无关分组添加等式。
3. 标签页 1 直接确认仍会成功；预览只锁定所涉分组及其关联判定/等式，无关分组的变化不会阻塞。

## 数据与配置

### CSV

默认文件：`data/suppliers.csv`

支持中英文表头别名：

| 含义 | 可识别表头 |
| --- | --- |
| 来源 | `来源`, `source`, `系统`, `采购系统` |
| 源编号 | `源编号`, `source_code`, `code`, `编号` |
| 企业名称 | `企业名称`, `name`, `企业名`, `供应商名称` |

首次导入按行顺序取前 `SEED_LIMIT` 条（默认 100）。要使用自己的 CSV，可在首次启动前替换该文件，或通过环境变量指定挂载路径：

```yaml
environment:
  SEED_CSV: /app/data/my_suppliers.csv
  SEED_LIMIT: "100"
```

也可在 `docker-compose.yml` 中新增只读挂载：

```yaml
volumes:
  - ./my_suppliers.csv:/app/data/my_suppliers.csv:ro
```

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_PATH` | `./data/review.db` | SQLite 数据库路径；Compose 中为 `/data/review.db` |
| `SEED_CSV` | `./data/suppliers.csv` | 首次导入的 CSV |
| `SEED_LIMIT` | `100` | 首次导入的最大记录数 |
| `APP_INSTANCE` | 主机名 | 页面展示的 Web 进程标识 |

## 行为与一致性规则

1. **原始记录不可变**：API 不提供修改/删除记录的入口；数据库还有 `BEFORE UPDATE/DELETE` 触发器直接拒绝修改。CSV 只在 `records` 表为空时导入。
2. **判定唯一**：规范化记录对 `(min_id, max_id)` 上最多一条判定。重复添加相同判定会被拦截；对已有相反判定的记录对重新判定也会被拦截。
3. **同一企业传递成组**：分组是“同一企业”边的连通分量。
4. **不同企业是硬约束**：任一“不同企业”判定连接的两个分组不得合并；端点已经在同组时添加“不同企业”判定会被拒绝。
5. **换算等式按记录归属、按组共享**：等式挂在原始记录上（每记录最多 20 条，数量为正整数、单位非空且不同），同组记录的等式构成一张无向换算图；查询只使用当前组的图，支持反向与多跳，结果为精确最简分数。
6. **闭环比例唯一**：同一组（含拟合并的拟组）内相同两个单位只允许一个比例；等式新增与分组合并的预览、确认都会校验，矛盾即拒绝并指出具体等式。
7. **预览快照**：服务端计算并保存一份快照，包含所涉原组成员、完整组员、关联判定以及这些组内的全部换算等式。页面展示受影响记录的变更前/变更后分组、组员、判定依据与等式。
8. **确认**：在 `BEGIN IMMEDIATE` 写事务中重新读取当前数据，先对拟组合并做等式闭环校验，再重建快照与预览逐字段比较：
   - 比例矛盾 → 409 `merge_unit_ratio_conflict`，附矛盾等式，预览标记为 `stale`，不写入任何内容；
   - 快照不一致（相关成员、关联判定或组内等式变化）→ 409 `preview_stale`，要求重新预览；
   - 一致 → 在同一事务内写入/删除判定或等式、重算并覆盖保存分组表，再将该预览标记为 `confirmed`。
   与所涉分组无关的变化不在快照内，因此不会影响确认。
9. **失败保留原状态**：判定、分组与等式在同一事务提交；任何异常回滚，原有数据保持不变。
10. **重启保留**：判定、预览、分组与换算等式均在 SQLite 中；启动时若记录已存在则不重新导入，并依据判定重算、规范化分组表。
11. **并发**：两个进程各自按请求打开 SQLite 连接；WAL 允许多读单写，`BEGIN IMMEDIATE` + `busy_timeout` 串行化写事务。等式增删与关系确认并发时，各自按最新状态校验并整体提交，不可能各自通过后形成矛盾组；同一个预览被并发确认时只有一次成功。

## API 摘要

同一组 API 会被 nginx 分发到两个进程，任意进程都能处理任意请求。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 当前记录、分组（含组内等式与单位）、判定依据、等式清单、同名候选对、统计与 `state_version` |
| `POST` | `/api/previews` | 创建预览：`{"operation":"add","record_a":1,"record_b":2,"relation":"same"}` 或 `{"operation":"withdraw","decision_id":3}` |
| `POST` | `/api/previews/{id}/confirm` | 确认；body `{"snapshot_digest":"..."}` 可选，用于校验页面持有的是同一预览 |
| `POST` | `/api/previews/{id}/cancel` | 取消尚未确认的预览 |
| `POST` | `/api/equations` | 新增等式：`{"record_id":1,"qty_a":2,"unit_a":"箱","qty_b":24,"unit_b":"件"}`；矛盾返回 409 并附矛盾等式 |
| `POST` | `/api/equations/delete` | 删除等式：`{"equation_id":3}` |
| `POST` | `/api/conversion/query` | 换算查询：`{"record_id":1,"unit":"盒","quantity":2}`；无通路时 `reachable=false` 并给出缺失提示 |
| `GET` | `/convert` | 包装单位换算页 |
| `GET` | `/health` | 健康检查，返回进程实例 |
| `GET` | `/api/meta` | 初始化信息与预览状态统计 |

冲突预览返回 HTTP 200，但 `preview.confirmable=false` 且附带 `conflict.code/message/evidence`；过期确认与等式比例矛盾返回 HTTP 409。

换算查询成功响应示例：

```json
{
  "ok": true,
  "query": {
    "record": {"id": 1, "source": "采购系统A", "source_code": "A-001", "name": "华信精密制造有限公司"},
    "unit": "盒", "quantity": 2, "target_unit": "件",
    "reachable": true,
    "rate_per_unit": "4",
    "result_numerator": 8, "result_denominator": 1,
    "result_text": "8", "is_integer": true, "hops": 2,
    "used_equations": [ {"id": 2, "text": "3盒=1箱", "record": {"...": "来源记录"}},
                         {"id": 1, "text": "2箱=24件", "record": {"...": "来源记录"}} ],
    "state_version": "135c818c332b24c6195"
  }
}
```

## 本地开发与测试

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --port 8000
```

浏览器打开 http://localhost:8000（审校页）与 http://localhost:8000/convert（换算页，单进程本地模式）。

运行测试：

```bash
pytest -q
```

测试覆盖（共 37 个用例）：

- 主体审校：首次导入上限与记录不可变、同关系传递、不同关系冲突、撤回单条判定、跨进程预览/确认、相关改动导致预览过期、无关改动不阻塞确认、同一预览只能确认一次、持久化分组表与重启恢复；
- 单位换算：精确分数/反向/多跳图搜索、闭环比例矛盾检测、入参校验、每记录 20 条上限、重复等式拦截、删除与缺失通路提示、组内来源隔离与拆分恢复、合并预览/确认的拟组冲突、并发下按最新状态整体校验、失败不改状态与重启保留。
